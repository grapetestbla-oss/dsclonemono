# ritual-maksim.by — редизайн

Новая версия одностраничного сайта ритуальной службы «Максим» вместо текущего
сайта на Tilda. Чистый HTML + CSS + ~230 строк JS, без конструктора, фреймворков
и сборки.

```
ritual-maksim/
├── index.html          # вся страница, контент и разметка
├── styles.css          # дизайн-система и адаптив
├── main.js             # меню, модалки, табы, маска телефона, отправка заявок
├── send.php            # приём заявок → Telegram (для хостинга с PHP)
├── config.example.php  # шаблон настроек бота → скопировать в config.php
├── .htaccess           # закрывает config.php и служебные файлы на Apache
└── telegram-worker/    # то же на Cloudflare Workers (для хостинга без PHP)
```

Посмотреть локально: `python3 -m http.server -d ritual-maksim 8000` →
http://127.0.0.1:8000

**Проблемы, которые нашёл:**

- **Отзывы с чужим названием.** Два из семи отзывов благодарят «Добрую
  услугу» и «Добрые услуги», а не «Максим». Посетитель это замечает, и доверие
  ко всем отзывам падает. В новую версию я их не перенёс; остальные отзывы
  взяты дословно.
- **Главное действие спрятано.** На мобилке в первом экране нет крупной кнопки
  звонка, и при прокрутке тоже нет. Для ритуальной службы звонок — основная
  конверсия. В новой версии кнопка звонка стоит в первом экране, а внизу
  закреплена панель «Позвонить / Viber / Перезвоните».
- **Памятка «что делать» зарыта** под списком услуг, хотя человек в стрессе
  ищет именно её. Перенёс её сразу под первый экран и сделал вкладки «дома /
  в больнице».
- **14 одинаковых форм** («Заказать бальзамирование», «Заказать копку
  могилы»…) с одинаковыми полями — это они раздувают HTML. Здесь одна модалка
  заявки: тема подставляется из того места, откуда её открыли.
- **Пустые блоки и ленивые картинки:** слайдеры салона и памятников при
  загрузке показывают пустые области, у героя справа пустое место.
- **SEO и meta:** в description опечатка («Ритуальные услугу»), в заголовках
  «агенство», `og:description` пустой, title говорит только про Несвиж, хотя
  салонов пять. Нет микроразметки организации. Исправлено, добавлен
  JSON-LD `FuneralHome` со всеми адресами и телефонами.
- **Стена SEO-текста** внизу страницы, которую никто не читает. Полезное из неё
  (договор, фиксированная цена, бесплатный выезд) разнесено по блокам.
- **В подвале «Понравился сайт? Связаться с разработчиком»** — реклама
  разработчика на сайте похоронной службы. Убрано.

## Что сделано

- Спокойная тёмно-тёплая палитра с шампанским золотом (фирменные цвета
  сохранены) и светлые «бумажные» секции для ритма. Заголовки — Playfair Display,
  текст — Manrope. У обоих нормальная кириллица.
- Первый экран: понятное обещание, звонок одним нажатием, 4 ключевых факта,
  свеча с живым пламенем как единственный декоративный элемент.
- Порядок блоков идёт от срочного к справочному: памятка → услуги → почему мы →
  агент → салоны и адреса (с маршрутом в Яндекс.Картах) → о службе → отзывы →
  вопросы → заявка.
- 13 услуг в одной сетке, подробности в модальном окне (тексты с текущего сайта).
- Доступность: семантическая разметка, фокус с клавиатуры, `prefers-reduced-motion`
  отключает анимации, контраст текста в норме.
- Без JS работают телефоны, ссылки, FAQ (`<details>`) и адреса.

## Что нужно, чтобы запустить в прод

1. **Настроить заявки в Telegram** (см. раздел ниже).
2. **Фото.** Сейчас на сайте нет фотографий: вместо портрета агента стоит
   монограмма, салон показан цифрами. Если есть реальные фото агента,
   зала, катафалков и салонов, их стоит добавить (в WebP, с `loading="lazy"`).
3. **Политика конфиденциальности.** Ссылки ведут на текущую страницу
   `/politika-konfidencialnosti`; при переезде с Tilda её нужно перенести.
4. **Проверить факты.** Цифры и формулировки взяты с текущего сайта
   (8 катафалков, 50 видов гробов, 120 венков, 30 минут, рассрочка 0% и т.д.).
   Если что-то устарело, это правится прямо в `index.html`.
5. Выложить файлы на хостинг и переключить DNS.

## Заявки в Telegram

Формы отправляют `POST` JSON `{name, phone, topic, page, website}` на адрес из
константы `LEAD_ENDPOINT` в начале `main.js` (по умолчанию `send.php`).
Обработчик проверяет номер (+375 и 9 цифр), отсекает ботов скрытым полем
`website`, экранирует текст и шлёт сообщение через Bot API. Токен бота хранится
только на сервере и в браузер не попадает.

Так выглядит заявка в Telegram:

```
🕯 Новая заявка с сайта

Тема: Копка могилы
Имя: Анна
Телефон: +375 44 775-57-11
Страница: https://ritual-maksim.by/
27.09.2026 15:03
```

Тема подставляется сама: из какой услуги или кнопки открыли форму.

### 1. Создать бота и узнать chat_id

1. В Telegram написать [@BotFather](https://t.me/BotFather) → `/newbot` →
   придумать имя. Он пришлёт **токен** вида `123456789:AAE...`.
2. Куда слать заявки:
   - **лично себе** — написать своему боту `/start`;
   - **в общий чат сотрудников** — создать группу и добавить в неё бота.
3. Открыть в браузере `https://api.telegram.org/bot<ТОКЕН>/getUpdates` и найти
   `"chat":{"id": ...}`. Для лички это число, для группы — отрицательное
   (`-100...`). Если ответ пустой, отправьте боту/в группу любое сообщение и
   обновите страницу.

### 2а. Хостинг с PHP (hoster.by, Beget, любой shared-хостинг)

1. Загрузить всю папку `ritual-maksim/` в корень сайта.
2. Скопировать `config.example.php` → `config.php` и вписать
   `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`. Несколько получателей — через
   запятую: `'111111111, -1002222222222'`.
3. Проверить: отправить заявку с сайта — сообщение должно прийти в Telegram.

Нужен PHP 7.4+ с `mbstring` (есть почти везде); `curl` желателен, но не
обязателен. Вместо `config.php` можно задать переменные окружения с теми же
именами. Защита: не больше 5 заявок с одного IP за 10 минут, по желанию —
только с вашего домена (`ALLOWED_ORIGIN`).

### 2б. Хостинг без PHP (GitHub Pages, Netlify, Cloudflare Pages)

Обработчик запускается как бесплатный Cloudflare Worker:

```bash
cd ritual-maksim/telegram-worker
npx wrangler login
npx wrangler secret put TELEGRAM_BOT_TOKEN
npx wrangler secret put TELEGRAM_CHAT_ID
npx wrangler deploy        # выдаст адрес вида https://ritual-maksim-leads.<имя>.workers.dev
```

Затем в `main.js` заменить `LEAD_ENDPOINT = "send.php"` на выданный адрес.
В `wrangler.toml` указан `ALLOWED_ORIGIN = "https://ritual-maksim.by"`: заявки
принимаются только с этого домена. Ограничение частоты для Worker настраивается
в панели Cloudflare (Security → WAF → Rate limiting rules).

### Если Telegram на сервере недоступен

Если хостинг не может достучаться до `api.telegram.org`, задайте
`TELEGRAM_API_BASE`: адрес прокси или своего Bot API сервера.

### Если что-то не пришло

Посетитель при ошибке видит «Не удалось отправить заявку. Позвоните нам: …»,
так что обращение не теряется молча. Причина пишется в лог ошибок PHP
(`send.php: ...`), а ответ обработчика видно во вкладке Network:
`config` — не заполнены токен или chat_id, `telegram` — Telegram отклонил
запрос (неверный токен, бот не добавлен в группу или ему не писали `/start`).
